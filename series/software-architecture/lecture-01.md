# 소프트웨어 아키텍처 1차시

### 좋은 코드란

- 유지보수가 용이하고
- 재사용성이 좋은 것

### 객체지향이 나온 이유

- 기존에 C 같은 절차적 언어에서 프로그램이 커질 수록 데이터와 함수를 구분짓는 게 어려워짐
  - 절차지향에서는 <b>데이터</b>와 <b>데이터를 다루는 함수</b>가 따로 흩어져 있었습니다.
    
    → 예를 들어 struct Account와 deposit(account, amount) 함수가 분리돼 있죠.
    
  - 이렇게 흩어져 있으면,
    - 데이터 구조가 바뀌면 관련된 모든 함수를 고쳐야 하고,
    - 데이터-함수 관계가 코드 전체에 흩어져 관리가 어려워집니다.

➡️ 그래서 <b>“같은 문제 도메인에 속하는 데이터와 그 데이터를 다루는 행동을 하나의 객체 단위로 묶자”</b> 라는 발상이 나온 겁니다.

- 이후에 구조적 프로그래밍에서 스파게티 코드를 해결하려고 햇으나 완벽하지 않음
- 그래서 객체지향 프로그래밍을 도입함
  - 이를 통해서 데이터와 함수를 모아둘 수 있게 됨
  - 유지보수성과 재사용성이 올라감

### 수동적인 객체

- 우리가 만든 건 대부분이 다 수동적인 객체
  - e.g. 서비스나 웹사이트
    - 외부 요청이 없으면 반응을 하지 않음
  - 예를 들어 내가 구매를 원하면, 그걸 구현한 클래스에 요청을 해야함

### 능동적인 객체

- 최근에 나오는 객체
- ai 들이 스스로 객체를 생성하고 외부 요청이 없어도 능동적으로 동작함
