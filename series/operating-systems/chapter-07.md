## 교착상태 특징

- 교착상태는 아래 4가지 조건이 모두 만족될 때 발생함
  1. 상호 배제
     1. 할당 후 반환까지 한 프로세스만 사용하는 자원이어야 함
     2. 만약 다른 프로세스가 그 자원 요청하면, 요청한 프로세스는 자원이 emit 될 때까지 지연되어야 함
  2. 점유하며 대기
     1. 각 프로세스가 <span color="orange">하나의 자원을 보유</span>하고, 현재 다른 프로세스에게 점유된 자원을 추가로 얻기 위해 반드시 대기하여야 함
        1. 중요 ) <span color="orange">하나의 자원을 보유</span>해야 하는 이유는, 나는 다른 프로세스의 자원을 요청하고, 다른 프로세스는 나의 자원을 요청해야 교착상태가 발생하기 때문임. 다른 프로세스가 나의 자원을 원하지 않은 상태에서, 나만 다른 프로세스의 자원을 원하고 있다면 그냥 대기한 다음에 받으면 되기 때문에 교착 상태가 발생하지 않음
  3. 비선점
     1. 자원은 그 자원을 점유한 프로세스로부터 강제적으로 방출될 수 없고, 자발적으로만 방출될 수 있음
  4. 환형 대기
     1. 대기 프로세스의 집합에서 p(n) 은 p(n+1) 이 가진 자원을 기다려야 함. 마지막 프로세스는 처음 프로세스의 자원을 기다려야 함
        1. 이게 깨지면 교착상태 발생 안함. 왜냐면 그래프에서 사이클이 발생하지 않기 때문. 사이클이 생겨야 교착상태임

## 교착상태를 다루기 위한 시스템 모델

### 자원

- 종류에 따라 분류됨 (R1, R2 …)
- 각 종류 별 여러 개의 개체가 있음 (R1 에는 r1, r2 …)
- 자원을 사용하려면 프로세스가 반드시 요청해야 하고, 사용 후에 반드시 방출(해제) 해야함
  - 요청 : 요청이 즉각 받아들영지지 않으면 대기 (요청 가능한 수는 총 자원 개수를 넘지 못함)
  - 사용 : 자원을 사용할 수 있는 상태
  - 해제 : 사용이 끝난 후 돌려줌
- 시스템 호출을 통하게 되어 있어 운영체제는 시스템 테이블에 자원할당 상황을 기록함

## 교착상태 처리 방법

### 교착상태가 되지 않도록 사전에 조치

- 교착상태 예방
  - 교착 상태 발생의 4가지 필요충분조건 중 하나라도 일어나지 않게 하는 것

  1. 상호배제 조건을 부정
     1. 이건 필수적임
     2. 일반적으로 상호배제를 부인할 수는 없음
  2. 점유하여 대기 조건을 부정
     1. 첫 번째 방법은 모든 자원을 실행 전에 확보하도록 하는 것
        1. 이러면 대기할 필요가 없음. 왜냐면 필요한 자원이 모두 잇으니까
        2. 그래서 ‘대기’ 조건을 부정할 수 잇음
     2. 두 번째 방법은 자원을 가지고 있지 않은 경우에만 자원을 요청할 수 잇게 하는 것
        1. 가지고 있는 자원을 해제한 후 추가 자원과 함께 다시 요청하는 것.
        2. 이 경우에는 점유하지 않기 때문에, 다른 프로세스가 내가 사용하던 자원을 요청할 수 있음

     ![운영체제 7장 이미지 7]({{ '/series/operating-systems/assets/os-08-007.png' | relative_url }})
  3. 비선점 조건을 부정
     1. 자원을 보유한 프로세스가, 지금 할당 받을 수 없는 자원을 요청한다면<b> 대기상태로 들어가면서 현재 할당 받은 것을 강제로 반환</b>하도록 하면 됨
        1. 반환된 자원에 대해서는 다른 프로세스가 선점 가능
        2. 대기 상태로 들어간 프로세스가 재시작 될 때에는 가지고 있던 자원과 대기 상태에 들어갈 때 요청한 자원을 모두 할당받아야 함
     2. 이 방법은 상태의 보존과 복구가 필요함
        1. 레지스터나 메모리를 대상으로는 가능하겟지만, 일반적으로 입출력 장치, mutex, 세마포어 등에 적용하기는 어려움
  4. 환형대기 조건을 부정
     1. 각 자원 유형에 증가하는 순서의 일련번호를 부여
     2. 번호가 증가하는 순서대로만 자원을 요청하도록 강제함
     3. 그니까, 각 자원마다 번호를 붙이고, 자기가 가진 자원에 적힌 숫자보다 큰 숫자를 가진 자원만 요청하게 하는 거. 만약에 자기가 가진 것보다 작은 숫자를 가진 자원을 요청한다면, 내가 지금 가진 자원을 모두 반납하여야 요청할 수 있게 하는 거임
        1. 이러면 환형대기 상태의 마지막 (p(n) 이 p(0) 의 자원을 요청하는 경우) 에 p(n) 의 자원이 p(0) 의 자원을 요청하므로, 즉, 자기가 가진 자원보다 낮은 숫자의 자원을 요청하므로 자신의 자원을 모두 반납하고, 그로 인해 p(n-1) 이 자원 획득 … 되어 환형대기가 깨짐
        2. 다시 말하자면,  <b>사이클을 만들려면 </b>언젠가는 누군가 <b>자기보다 번호가 더 작은 자원을 요청 </b>해야 하기 때문임

### 교착상태 방치 후 탐지하여 복구

- 교착상태 회피
  - 예방 대책은 자원의 활용도 낮게 하고, 시스템 처리량 감소시키거나 기아상태가 발생할 수 있음
  - 회피
    - 프로세스에게 더 많은 정보를 제공받은 다음에, 자원을 할당하지 않고 기다려야 할지 말지를 결정
    - 현재의 요구가 만족될 수 있는지, 미래의 가능한 교착상태를 회피하기 위해 기다려야 하는지 결정하는 것
- 시스템의 순서가 안정하다라는건
  - 프로세스가 최대 자원을 요청하더라도 교착상태가 발생하지 않고 자원을 할당할 수 있게 하는 것
  - <b>교착상태의 회피는, ‘새로운 자원을 할당했을 때에도 안정상태가 유지될 수 있는가?’ 에 따라서 행동하는 것</b>

### 교착상태 탐지

- 교착상태 예방,  회피 등을 사용하지 않을 경우, 교착상태를 검사하는 알고리즘을 주기적으로 수행

## 교착상태 복구

1. 프로세스를 종료하고 자원 회수
2. 교착상태에 있는 하나 이상의 프로세스로부터 자원을 선점

### 종료해서 해결하는 방법

- 교착상태 프로세스를 모두 중지하거나
  - 단점 ) 비용이 매우 큼. 왜냐면 처리하던 걸 다음에 다시 해야 하기 때문
- 교착상태가 제거될 때가지 하나씩 중지
  - 단점 ) 교착 상태 탐지 알고리즘을 사용하는 오버헤드 감수해야함
- 종료시킬 프로세스 선정 요소
  - 프로세스 우선순위
  - 얼마나 오랫동안 수행햇나? 얼마나 더 수행되나?
  - 사용한 자원타입과 수
  - 작업 마치는데 얼마나 더 자원이 필요한지
  - 복귀하는데 얼마나 많은 프로세스가 포함되어 있는지
  - 프로세스가 대화형인지 일괄처리인지

### 선점해서 해결하는 방법

- 교착상태에 있는 프로세스가 갖고 있는 자원을 계속적으로 선점하여 다른 프로세스에게 주는 방식
  - 이게 가능하려면 롤백(후퇴) 가 필요함
  - 안정상태로 롤백하고 그 상태로부터 다시 시작하는 것
  - 일반적으로 안정상태를 결정하기 어렵고, 각 프로세스의 상태정보를 더 많이 관리해야 함
  - 가장 단순한 해결책은 total rollback (abort & restart)
- <b>Q. 모든 프로세스가 선점 불가능한 자원만을 사용하고 있다면?</b>
  - 이러면 선점 기반 복구는 불가능하고, 롤백이나 종료같은 강제적인 방법으로 해결해야함

### cf ) 롤백해서 해결하는 방법

- 롤백해서 해결하려면, 새로운 자원이 할당되기 바로 직전의 상태를 계속해서 백업을 해두어야 함
- 추가로, 트랜잭션 시작 시점, 주기적으로 백업 하는 과정도 필요함
- 선점 불가능하거나 롤백 위험이 큰 자원만 백업하는 전략도 있음
- 백업 데이터는 메모리나 디스크에 저장됨
