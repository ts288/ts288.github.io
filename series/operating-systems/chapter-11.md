# 운영체제 11장

## 대용량 저장구조

## 섹터 접근의 구성 요소

- 3가지 시간지연요소
  - 탐색요소
    - 회전하는 트랙에서 원하는 섹터 찾는 시간
  - 회전지연시간
    - 회전하는 시간
  - 전송시간
    - 읽거나 쓰거나 지우거나 하는 시간
- I/O Request 중에 hard disk 에서 데이터 읽는 request 가 a, b, c 라면, 그 요청이 순서대로 디스크 입출력 요청 queue 에 들어옴
  - 근데 꼭 순서를 지켜야 하는 건 아님! 제일 시간 지연이 적은 것부터 먼저 처리해도 돼
    ![운영체제 11장 이미지 1]({{ '/series/operating-systems/assets/os-12-001.png' | relative_url }})

    - 여기서 a 읽은 다음에 c 읽는 게 더 좋음
  - 즉, 스케줄링 후에 최적의 순서로 움직임

### 디스크 스케줄링

- 섹터들이 하드 디스크에 물리적으로 순차적 저장이 안되기 때문에 스케줄링이 필요함
- 디스크 스케줄링이란 어느 프로세스의 요청을 먼저 선택하여 실행할 것인지 순서를 결정하는 것
- 목적 - 처리율의 극대화
  - 평균 반응시간 줄이기
    - 어떤 요청이 디스크 구동기에 전해질 대부터 그 결과가 나올 때까지의 시간의 평균값을 줄이는 것
  - 반응시간 분산 줄이기
    - 디스크 입출력 시간의 예측성을 향상시키는 것
    - 어떤 요청은 빨리, 어떤 요청은 느리게 처리되면 작업 완료 시간을 예측할 수 없음. 그래서 반응시간과 분산을 줄이는 것

### 스케줄링 알고리즘

- FCFS
  - 가장 간단함
  - 먼저 도착한 요청이 우선적으로 서비스 받음
  - 특징
    - 대기 큐를 재배열 하지 않음
    - 탐색 패턴을 최적화 하려고 하지 않음
    - 우선순위 영향 안받음
  - 장단점
    - 공평성이 보장됨
    - 프로그래밍이 쉬움
    - 요청이 많아지면 평균응답 시간이 길어짐
    - 효율이 낮음
- SSTF
  - 탐색거리가 가장 짧은 요청이 먼저 서비스 받음
  - 특징
    - 헤드가 이동하기 전에, 현재 위치에서 최소의 탐색시간 요하는 요청부터 찾아서 처리
  - 장단점
    - FCFS 보다 처리량이 많고 평균 응답시간이 짧음
  - 바깥쪽 트랙은 가운데 있는 트랙보다 훨씬 서비스 덜 받게 됨. 그래서 기아가 발생하거나, 응답시간 편차가 생길 수 있음
  - 처리량이 주요 목표인 일괄처리시스템에 유용
  - 응답시간 편차가 크므로, 대화형 시스템에는 부적합함
  - 이걸 해결하기 위해 scan 및 look 스케줄링 사용
- SCAN 및 LOOK
  - SSTF 의 응답편차의 차별대우와 큰 편차를 극복하기 위해 고안
  - 엘리베이터 알고리즘이라고도 함
    - 진행하는 방향으로만 탐색함
  - SCAN과 LOOK 스케줄링의 차이
    - SCAN에서는 움직임이는 방향의 앞으로 더 요청이 없으면, 인위적으로 헤드를 디스크 끝까지 이동한 후에 다시 방향을 바꾸는 방법
    - LOOK에서는 움직이는 방향으로 더 이상 요청이 없으면 끝까지 가지 않고 그 자리에서 다시 반대 방향으로 헤드를 움직이는 방법
  - 특징
    - 대긱큐의 동적인 특성을 효율적으로 반영
    - 처리량과 평균 응답시간 개선 & 차별대우 (편차) 많이 없앰
    - <b>그러나 응답시간 편차는 여전히 있음</b>
      - 헤드 진행 도중 새로 도착한 요청도 함께 서비스 받게 되므로, 밖에 위치하는 트랙은 더 적은 서비스를 받을 수도 있음
      - 가운데 트랙에 요청이 계속 생기면 끝에 있는 게 서비스 못바등ㅁ
    - 실제로 구현하는 대부분의 디스크 스케줄링의 기본 전략
- C-SCAN
  - c 는 circular 의 약자
  - 한 방향으로만 움직이면서, 트랙의 끝에 도달하면 다시 헤더를 처음 위치로 정렬
  - scan 과 c-scan 비교
    - scan 은 안쪽과 바깥쪽 대한 요청이 불리
    - c-scan 은 헤드가 마지막 트랙으로 이동하게 되었을 때, 반대 방향으로 가지 않고 다시 0트랙으로 움직이기 시작
  - c-scan 은 복귀시간이 필요하나, 처리시간이 공평함
- 회전지연시간 최적화
  - SLTF 스케줄링 (근본)
    - 얼만큼 회전하는데 더 오래 걸리나 를 보는 것
    - 요청들의 도착 순서에 상관없이, 섹터위치에 따라 큐에 넣고 가장 가까운 섹터에 대한 요청을 먼저 서비스함
  - SPTF 와 SATF 스케줄링 (안중요)

    </li>
