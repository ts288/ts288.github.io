# 싱글톤 동작과 멀티스레드

### Q. 멀티스레드 환경에서 여러 요청이 동시에 하나의 객체에 접근한다면, race condition 같은 문제가 발생하지 않을까?

```kotlin
예를 들어,
1. 어떤 객체가 (userId, request)를 받아 요청을 가공하고 전송한다.
2. 스레드 A가 (a, reqA)를 보낸다.
3. 스레드 B가 (b, reqB)를 보낸다.
4. A의 요청이 먼저 가공된다.
5. 그 사이 B의 요청도 가공된다.
6. A가 전송을 시도하는 순간 → a의 ID와 b의 요청이 섞여 전달될 수 있다 (❗️Race Condition)
```

### A. 발생할 수 있다! 하지만 객체와 메서드의 원리를 잘 이해하고 구현하면 방지 가능하다.

### 먼저 클래스, 객체, 메서드, 스레드의 차이부터!

- 클래스
  - 설계도
  - 어떤 행동(메서드), 어떤 속성(필드)을 가질지 정의
- 객체
  - 클래스(설계도)를 바탕으로 런타임에 생성된 <b>실체</b>
  - 필드(상태)를 가지며, 메서드(행동)를 실행할 수 있음
  - 그러나 <b>자기 스스로 실행하지는 않음!</b>
- 메서드
  - 객체 내부에 소속된 함수!
  - 호출될 때마다 <b>스레드의 호출 스택(stack)</b> 위에 독립적으로 실행 컨텍스트가 생성됨
- 스레드
  - 실제 작업을 수행하는 주체
  - 객체의 메서드를 실행하며, 이때 필요한 <b>매개변수/지역 변수</b>는 자신의 스택에 쌓음
  - 각 스레드는 자기 스택 위에서 메서드를 실행하므로, <b>메서드 실행은 스레드마다 완전히 분리됨</b>

### 그래서 최종적으로 동작하는 방식은,

> 런타임 시 클래스 설계에 따라 객체가 생성되고, 요청을 처리하는 스레드는
>
> 해당 객체의 메서드를 호출하여 로직을 수행한다.
>
> <b>이때 각 스레드는 메서드의 실행 컨텍스트(지역 변수, 매개변수 등)를 자기만의 스택에 올려 독립적으로 실행한다.</b>

➡️ 따라서 같은 객체를 공유하더라도, <b>공유 필드만 조심하면</b> 각 요청은 안전하게 처리된다!

## 싱글톤 방식을 사용하면!

- <b>객체 자체는 하나</b>이므로 모든 요청이 공유한다.
- 하지만 <b>메서드는 실행될 때마다 스레드 스택에 독립적으로 쌓이기 때문에</b>, 지역 변수나 매개변수를 사용하는 한에서는 충돌이 없다!
  - 단, 전역 변수와 같은 부분은 스레드끼리 공유하니, spring 에서는 전역 변수를 사용해서는 안된다! (대부분이 bean 으로 관리되기 때문!)

### 그러니까, spring 에서는 지역 변수 사용은 그냥 하지 마라!

- 대부분이 singleton 패턴이기 때문에, 그냥 사용 안 하는 게 나음!
